# 代码使用与管理方法建议

## 建议：一个 git 仓库 + 每个分析一个 worktree

这个方案的好处是**完全保留你现在的习惯**（每次分析一个独立的物理目录），但目录不再是"拷贝"，而是同一个版本库的"工作区"。

### 1. 一次性初始化（在总仓库里）

```bash
cd /path/to/总仓库          # 你放总代码的地方
git init
# 先写 .gitignore（关键，否则几十 MB 的录波 CSV 会进库）
cat > .gitignore <<'EOF'
# 脚本自动生成的输出目录
DA01c_*/
T01_*/
T02b_*/
SWFFT_*/
output*/
# 录波数据（太大，不入库）
*.csv
# MATLAB 自动保存 / 系统文件
*.asv
.DS_Store
EOF
git add -A
git commit -m "初始提交：滑动窗分析模板与公共函数"
```

### 2. 每次做一次振荡分析（替代"拷一份"）

```bash
cd /path/to/总仓库
git worktree add "/你的工作目录" \
    -b analysis/your_work_name
```

之后就在这个目录里照常改、照常跑。`git worktree list` 能看到你所有的分析目录。

### 3. 把功能合并回总仓库

```bash
cd /path/to/总仓库
git log --oneline analysis/your_work_name   # 找到「功能」提交的短 hash
git checkout main
git cherry-pick <hash>                            # 只把功能提交挑回来
```

## 最关键的一条纪律：提交要分两类

这是让「合并」变简单的核心。改完之后**分两次提交**：

| 提交前缀         | 内容                                           | 是否回并                |
| ---------------- | ---------------------------------------------- | ----------------------- |
| `feat:` / `fix:` | 通用改进（函数、模板、bug 修复）               | ✅ 要 cherry-pick 回主库 |
| `cfg:`           | 本次故障专属（CSV 名、列关键词、时间窗、频率） | ❌ 留在分支上            |

```bash
git commit -am "cfg: 本次故障的 CSV / 关键词 / 时间窗"
git commit -am "feat: f_top_peaks 增加检索频段参数"
```

这样 `cherry-pick` 只挑 `feat`，**既不会漏文件，也不会把本次故障的配置带进总仓库**。懒得分开提交时，用 `git add -p` 交互式分块暂存，只把功能那几块先提交。

## 更彻底的做法（可选，改动稍大）

把本次故障的所有参数（`CSV_FILE`、`POINT_KEYWORDS`、`t_span`…）集中到一个 `cfg_local.m`，脚本开头 `run('cfg_local.m')` 覆盖默认值，并把 `cfg_local.m` 加进 `.gitignore`。这样总仓库里永远只有干净的通用代码，合并时**根本不会产生冲突**，也就谈不上"漏"。

## 如果暂时不想上 git（退路）

至少先"看清改了哪些文件"，再决定拷哪些：

```bash
diff -rq /path/to/总仓库 /path/to/本次分析目录      # 列出所有差异
rsync -avn --delete /path/to/本次分析目录/ /path/to/总仓库/   # -n = 干跑，只打印不执行
```

这能解决「漏」，但「哪些该合并」仍要你人判断 —— 所以还是推荐 git。
